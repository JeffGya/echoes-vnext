Inventory UI click-through prototype, v2

v2 follows Jeff's review of v1 and decision D-33. The Sanctum inventory and the party pack are two separate panels. Pieces move both ways by drag and drop, or by select and a Move button. A stack is an item like any other. On a path, the pack is read-only except one discard. Result cards hold the items inside the existing card. All wording is placeholder. Placeholder text has a dotted underline, and the button Highlight placeholder wording marks it.

Prototype. Not the game. HTML only; the Godot build comes later.

A. The prototype

Pick a scenario. Drag a tile to the other panel, or select a tile and press Move to .... Keyboard: Tab to a tile, arrows move between tiles, Enter selects, Tab to the Move button, Enter moves. Esc closes a modal or a panel. Press M on a selected tile to move it.

    B. Tiles and marks

    One tile for every screen. A tile keeps its look on both sides: the bed is plain in the Sanctum and darker (and 2 px lower) in the pack. A stack is a tile with a second plate edge and a count. The same stack type can sit on both sides, even in several slots. The last row shows the same states in grayscale.

        G. Placeholder wording register

        Every player-facing string in the frame is a placeholder. Jeff writes the final copy. Item names such as "Test gear A" are placeholders too. Items are never shown as ids.

        All placeholder strings used in the frame
          Review proposal, not game implementation or approved final art. All wording is placeholder.
          Review focus: can a player always tell which pieces are in the pack and which are in the Sanctum, and does a move feel like lifting a piece from a chest into a bag?
          Grounding and limits

          Tile, marks, tokens and motion constants are reused from the v1 prototype (inventory-ui-mockup.html). The 1920 profile is dropped in v2. The page draws one 1280 x 720 frame and scales it to the page width.

          The Sanctum and the path view are stand-ins. Slot counts (Sanctum 20, pack 4) are prototype numbers, not the provisional values in data/balance.json. Item data, the leave draw and the path-end rule are small prototype rules. They do not read the game's core code.
